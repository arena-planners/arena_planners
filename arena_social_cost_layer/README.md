# arena_social_cost_layer

Nav2 `costmap_2d::Layer` that paints social cost from `arena_peds` (`arena_people_msgs/Pedestrians`): a super-Gaussian personal-space disk around every pedestrian (an anisotropic one around wheelchair users and pushed wheelchairs, below), widened for the `SURPRISED`/`CURIOUS` and `PANIC`/`THREATENING` animation states, plus a capsule along the segment between every pair of pedestrians sharing an active `interaction_id`, weighted per interaction kind by `interaction_weights`. Both terms stop at a hard radius (`personal_space_radius`, `group_extra_radius`), the sigmas set the falloff inside it and `falloff_shape` is the super-Gaussian exponent (1.0 is a plain Gaussian, larger values flatten the core and sharpen the edge).

Parameters under `<layer name>.`: `enabled`, `peds_topic`, `personal_space_radius`, `personal_space_sigma`, `group_extra_radius`, `group_sigma`, `falloff_shape`, `max_cost_value` (clamped to `INSCRIBED_INFLATED_OBSTACLE - 1`, 252), `stale_timeout` (seconds, older pedestrian messages are ignored), `cost_scale` and `cost_bias` (gain and floor on the normalized cost), `interaction_weights` (weight of the group term per interaction kind, a list indexed by humansim's `InteractionType`, a missing or zero entry paints no capsule for that kind), `anisotropic_classes`, `agent_types_dir`, `push_interaction_type`, `wheelchair_sigma_front`, `wheelchair_sigma_back`, `wheelchair_sigma_side`, `wheelchair_front_speed_gain`, `wheelchair_amplitude`, `wheelchair_cutoff` (the anisotropic term below, defaults 1.2, 0.9, 0.45 m, 0.5 s, 1.0, 2.5; it shares `falloff_shape`).

Wheelchair users get an anisotropic Gaussian instead of the disk, aligned with their heading: `wheelchair_sigma_front` ahead (growing by `wheelchair_front_speed_gain` times the speed), `wheelchair_sigma_back` behind and the narrower `wheelchair_sigma_side` beside, so passing ahead of or behind a chair costs more than passing beside it; nothing is painted past `wheelchair_cutoff` sigmas, `wheelchair_amplitude` is its peak. A chair being pushed (an active `push_interaction_type`, humansim's `PUSH_WHEELCHAIR` = 13) is painted as one body from the pusher's back to the chair's front along the chair's heading, with no disk for the pusher and no capsule for the pair. Which pedestrians count as wheelchair users is ground truth from humansim: the `interaction_class` of the pedestrian's `agent_type` (a builtin name, or a scenario yaml path whose `extends` chain is followed like humansim does), matched against `anisotropic_classes` (default `["wheelchair"]`, the class of `wheelchair_manual` and `wheelchair_electric`). Builtin types are read from `agent_types_dir`, by default `arena_humansim`'s share `config/agent_types`; a type that cannot be read is warned about once and treated as a plain pedestrian.

Robots on the Nav2 adapter load it into both costmaps with the `social_cost_layer` Nav2 overlay, `robot.mobile.params_overlay:=social_cost_layer` (`mobile.params_overlay: social_cost_layer` in a benchmark contest); the parameter blocks live in `arena_robots/config/nav2/overlays/social_cost_layer.yaml`.

`cost_math.hpp` holds the pure cost functions, covered by `test/test_cost_math.cpp`; `agent_class.hpp` resolves the classes, covered by `test/test_agent_class.cpp`:

```bash
arena build arena_social_cost_layer
arena test arena_social_cost_layer
```
